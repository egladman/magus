# BZZ3002: value accumulated in a loop

A value that outlives one pass of a `while`, `for`, `foreach` or `do` loop is
rebuilt from itself in a way that copies all of it:

- a list or map that is an operand of `+`, as in `xs = xs + [x]`,
  `xs = [x] + xs`, `xs += [x]` or `m = m + {k: v}`
- a `str` with text before it, either in a `+` chain or in an interpolated
  string, as in `s = x + s`, `s = "<" + s + ">"` or `s = "{x}{s}"`

```buzz
var out = "";
foreach (line in lines) {
    out = line + "\n" + out;   // BZZ3002
}
```

```text

  see: .../BZZ3002.md
```

A `for` post clause such as `s = "x" + s` warns the same way.

`+` on a list or map returns a new one, so each iteration copies everything
accumulated so far: the work is quadratic in the final size. A string is
immutable, and putting text before it copies it too. gopherbuzz adds a memory
cost on its default nanbox build. A `Value` encodes an index into a global
append-only object heap, so every intermediate copy stays reachable for the
life of the process.

Like [BZZ3001](BZZ3001.md) this is a **warning**: it never fails `Exec` or
`Compile`, and the program still runs.

## Resolution

Put the string first. Once a string reaches 1024 bytes, gopherbuzz extends it in
one shared buffer when it is the left end of a `+` chain or the first part of an
interpolation, so this loop costs linear time and memory:

```buzz
var out = "";
foreach (line in lines) {
    out = out + line + "\n";   // no warning
}
```

To build the string in the other order, collect the pieces in a list, reverse
it and join once:

```buzz
final parts: mut [str] = mut [<str>];
foreach (line in lines) {
    parts.append(line + "\n");
}
final out = parts.reverse().join("");
```

A list grows with `append()` on a `mut` list, and a map with `m[k] = v` on a
`mut` map.

## When it does not fire

`s = s + x`, `s += x` and `s = "{s}{x}"` stay quiet: the string leads its own
rebuild, so it extends in place. A string under 1024 bytes is copied on each
extension, but that copy is bounded.

Only the bare target as an operand counts. A rebuild that does not grow the value
stays quiet, because the copy does not accumulate:

```buzz
s = s.trim();                           // no warning
s = replace(s, a, b);                   // no warning
s = s.sub(0, len: i) + s.sub(j);        // no warning: a truncation
```

A value declared inside the loop body starts over each pass, so rebuilding it
there stays quiet too. A binding a `for` clause declares is made once, so it
counts as outside the loop.

An accumulator of any other type is not flagged either: `i = i + 1` allocates
nothing.

The check does not see a loop that also extends `s` somewhere else, such as
`final shown = s + "!"`. The shared buffer then holds the other extension, so
each `s = s + x` after it copies the whole of `s` again.
