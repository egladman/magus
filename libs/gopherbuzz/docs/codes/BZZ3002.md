# BZZ3002: string accumulated in a loop

A `str` variable is assigned a `+` expression that carries the variable itself,
inside a `while`, `for`, `foreach` or `do` body:

```buzz
var out = "";
foreach (line in lines) {
    out = out + line + "\n";   // BZZ3002
}
```

```text
[BZZ3002] buzz: line 3:5: warning: "out" is rebuilt from itself inside a loop, copying the whole string every iteration; collect the parts in a list and join() it once
  see: .../BZZ3002.md
```

Buzz strings are immutable, so each iteration allocates a fresh copy of
everything accumulated so far: the work is quadratic in the final length. On the
default nanbox build it is also a permanent memory cost. A `Value` encodes an
index into a global append-only object heap, so every intermediate copy stays
reachable for the life of the process and no garbage collection reclaims it. A
loop that builds a 2MB string this way has been measured at 13.1GB peak RSS.

Like [BZZ3001](BZZ3001.md) this is a **warning**: it never fails `Exec` or
`Compile`, and the program still runs.

## Resolution

Collect the pieces in a list and join once:

```buzz
final parts: mut [str] = mut [<str>];
foreach (line in lines) {
    parts.append(line + "\n");
}
final out = parts.join("");
```

The same loop that peaked at 13.1GB writing its output with `+` peaks at 29.5MB
written this way.

## When it does not fire

Only a bare `+` chain carrying the target counts. Rebuilding a string without
growing it stays quiet, because the copy is bounded:

```buzz
s = s.trim();          // no warning
s = replace(s, a, b);  // no warning
```

A non-`str` accumulator is not flagged either: `i = i + 1` allocates nothing.
