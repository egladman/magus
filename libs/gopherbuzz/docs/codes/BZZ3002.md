# BZZ3002: value accumulated in a loop

A `str`, list or map that outlives one pass of a `while`, `for`, `foreach` or
`do` loop is rebuilt from itself, either as an operand of `+` or as a part of an
interpolated string:

```buzz
var out = "";
foreach (line in lines) {
    out = out + line + "\n";   // BZZ3002
}
```

```text
[BZZ3002] buzz: line 3:5: warning: "out" is rebuilt from itself inside a loop, copying the whole string every iteration; collect the parts in a list and join() it once
  see: .../BZZ3002.md
```

`out = "{out}{line}\n"`, `xs = xs + [x]` and `m = m + {k: v}` warn the same way,
and so does a `for` post clause such as `s = s + "x"`.

In Buzz a string is immutable and `+` on a list or map returns a new one, so each
iteration copies everything accumulated so far: the work is quadratic in the
final size. gopherbuzz adds a memory cost on its default nanbox build. A `Value`
encodes an index into a global append-only object heap, so every intermediate
copy stays reachable for the life of the process. A loop that builds a 2MB
string this way has been measured at 13.1GB peak RSS.

Like [BZZ3001](BZZ3001.md) this is a **warning**: it never fails `Exec` or
`Compile`, and the program still runs.

## Resolution

Collect the pieces in a list and join once:

```buzz
final parts: mut [str] = mut [<str>];
foreach (line in lines) {
    parts.append(line + "\n");
}
final out = parts.join("");
```

The same loop that peaked at 13.1GB writing its output with `+` peaks at 29.5MB
written this way. A list grows with `append()` on a `mut` list, and a map with
`m[k] = v` on a `mut` map.

## When it does not fire

Only the bare target as an operand counts. Rebuilding a value without growing it
stays quiet, because the copy does not accumulate:

```buzz
s = s.trim();                           // no warning
s = replace(s, a, b);                   // no warning
s = s.sub(0, len: i) + s.sub(j);        // no warning: a truncation
```

A value declared inside the loop body starts over each pass, so rebuilding it
there stays quiet too. A binding a `for` clause declares is made once, so it
counts as outside the loop.

An accumulator of any other type is not flagged either: `i = i + 1` allocates
nothing.
