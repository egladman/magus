# BZZ1006: unhandled raise

A function declared with a `!>` error-set annotation - or a host function
authored as raising - can return an error to its caller instead of a value.
Buzz requires every such call to be handled one of two ways: propagate it by
declaring `!>` on the enclosing function too, or catch it with `try`/`catch`
(or the inline `expr catch default` form). This call did neither, so the error
would have nowhere to go.

```text
[BZZ1006] buzz: line 6:12: call may raise but is neither declared with !> nor caught
  see: .../BZZ1006.md
```

## Resolution

Pick one:

- Propagate: add `!> ErrType` to the enclosing function's signature, so its own
  callers take on the same obligation.

  ```buzz
  fun caller() > str !> str {
      return risky();
  }
  ```

- Catch: wrap the call in `try`/`catch`, or use the inline `catch` form, and
  handle the error where it happens.

  ```buzz
  fun caller() > str {
      try {
          return risky();
      } catch (e: str) {
          return "fallback";
      }
  }
  ```

Prefer catching over swallowing: a `catch` block that discards the error and
returns a placeholder recreates the silent-failure behavior this check exists
to prevent. Only swallow an error when the caller genuinely cannot act on it.
