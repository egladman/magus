# Outer harness

The deterministic scaffolding a repository adds around any
[inner harness](inner-harness.md): guard verdicts, job leases, the job store
and answers from the workspace graph, placed at points a person chose. It
judges and informs, and never rewrites what reaches the model
([The outer harness stays outside](../design/judgment/the-outer-harness-stays-outside.md)).
Birgitta Bockeler's
[Harness engineering](https://martinfowler.com/articles/harness-engineering.html)
names this layer.

- Is: magus's guard, leases and jobs, which serve every inner harness the same
  way.
- Is not: an agent loop, an orchestrator that drives loops, or a prompt.

## Example

Two inner harnesses take and return the same job row through the outer one:

```sh
magus job exec docs-fix
magus describe job docs-fix
```
