# Cantrip

One command a target runs itself with `proc\exec`. The target owns the argv,
the cache decision, and the failure. A spell is the library of tool-native
operations a project binds. A spell earns that binding when the operation
recurs and has cache inputs worth declaring.

`actionlint` in the root `lint` target and `trivy fs` in `security` are
cantrips. `trivy image` is an op on the `docker` spell, because the
vulnerability database keys that scan's cache. `shellcheck` is an op on the
`bash` spell, because shell is a language a project binds.

A file under `spells/` whose only purpose is to wrap one of those commands
does not earn the contract. `spells/actionlint` and `spells/trivy` would be
that file. A mise spell is the same refusal from the other side: magus does not
select, install, or move a toolchain version
([The line](../scope.md#the-line)). A `code/edit` spell written so its inputs
match `spells/code/search` is the same refusal again: that module is source a
magusfile imports, and it is not a registered spell. A shared schema with one
caller removes no failure.

[ADR 0017](../decisions/0017-a-change-accepts-the-findings-it-causes.md) uses
this word for a proposed rename of spell. That rename is not in this tree.
Author against this page.

## Example

`lint` runs actionlint over the workflows it already reads.

```buzz
proc\exec("actionlint", []);
```
