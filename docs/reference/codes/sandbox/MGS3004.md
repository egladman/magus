# MGS3004: magus version too old

The magus binary running this command is older than the minimum a workspace
declares it needs, via `requires_magus` in `magus.yaml`.

```text
[MGS3004] running magus v0.3.0 is older than this workspace requires (requires_magus: 0.4.0)
```

## Why

A magusfile can use a feature - a new host method, a config key, a target
policy - the moment it lands, without any capability negotiation: the author
knows what version they wrote it against, but nothing tells a reader running
an older binary. Left unpinned, that mismatch surfaces later as a confusing
failure (an unknown config key, a missing method) that reads like a bug in
the workspace rather than a stale binary.

`requires_magus` lets a workspace record the version it assumes, so the
mismatch is reported at load time, in one place, instead of wherever the
missing feature happens to be used.

## Resolution

1. Upgrade the running binary to at least the declared version (`magus self
   update`, or reinstall from the pinned release your CI uses).
2. If the workspace's `requires_magus` is newer than it needs to be, lower it
   to the actual minimum, or remove it if the pin was never load-bearing.

This is a warning, not a load failure: the run continues on the assumption
that most behavior is unaffected, but documented behavior from this point
forward may not match what actually runs.

## What is not checked

A locally built dev binary (a `-g<sha>` git-describe suffix, or the
unstamped `unknown` sentinel) has no reliable release version to compare, so
the check is skipped rather than guessed at. Only a clean tagged release is
compared against `requires_magus`.
