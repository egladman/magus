# MGS3048: a magus process from another build answered

A magus command reached a long-running magus process, and the process answered
from another build:

```text
[warn] [MGS3048] host capacity is not arbitrated for this run: a broker from
  another magus build answered (broker: best-effort)
  error: hello: the broker at ~/Library/Caches/magus/run/broker.sock is from
  another magus build (broker: expected a hello speaking protocol 2; this magus
  speaks protocol 1)
```

The process on the other end is one of:

- the **broker**, which arbitrates host capacity, refusing the hello because it
  speaks another protocol. A run says so once.
- the **server**, or a per-process **pool parent**, started by another magus.
  `magus server status` and `magus server status` name it, with its pid and build.
- the **MCP server**, started before its binary was rebuilt. Each tool result
  carries the line.

A process keeps running across an upgrade of the binary it was started from,
which is how two builds meet. A server or pool parent still speaking the socket
protocol from before the socket carried HTTP is the oldest case of this, and is
reported as [MGS3025](MGS3025.md) until that code folds in here.

## What still works

The command goes on without what that process serves:

- With the broker, steps run without a seat, so host capacity is not
  arbitrated. Under `broker: required` the same answer is an error instead,
  and the step does not start.
- With the server or a pool parent, a forwarded run warns once and runs
  locally, in its own process.
- With the server or a pool parent, every call through it is answered by the
  older build, which decodes what it knows.
- With the MCP server, calls are answered by the older build, which decodes what
  it knows.

## What to do

Restart the process so it runs this build:

```sh
magus server broker stop        # or kill -TERM <pid>; the next run starts one from this build
magus server stop && magus server start
```

`magus server broker stop` asks the kernel which process holds the socket and sends a
broker of another build `SIGTERM`, since that build may not understand a stop
request. Every magus process handles `SIGTERM` as a clean shutdown.
