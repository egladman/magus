# MGS3048: a magus process from another build answered

A magus command reached a long-running magus process, and the process answered
from another build:

```text
[warn] MGS3048 broker: host capacity is not arbitrated because a broker from
  another magus build answered (pid 41233, v0.4.3, protocol 2; this magus
  speaks 1); steps run without a seat
  fix: stop it with the build that started it (`magus broker stop`), or `kill -TERM 41233`;
  the next run starts one from this build
```

The process on the other end is one of:

- the **broker**, which arbitrates host capacity, speaking another protocol or
  predating a frame this build sends, such as memory overruns;
- the **server**, or a per-process **pool parent**, started by another magus;
- the **MCP server**, started before its binary was rebuilt.

A process keeps running across an upgrade of the binary it was started from,
which is how two builds meet. A server or pool parent still speaking the socket
protocol from before the socket carried HTTP is the oldest case of this, and is
reported as [MGS3025](MGS3025.md) until that code folds in here.

## What still works

The command goes on without what that process serves, and says so once:

- With the broker, steps run without a seat, so host capacity is not
  arbitrated. Under `broker: required` the same answer is an error instead.
- With the server, a forwarded run runs in its own process.
- With the MCP server, calls are answered by the older build, which decodes what
  it knows.

## What to do

Restart the process so it runs this build. The line names its pid and build:

```sh
magus broker stop        # or kill -TERM <pid>; the next run starts one from this build
magus server stop && magus server start
```

Stop it with the build that started it where you can. A process from another
build may not understand this build's stop request; every magus process handles
`SIGTERM` as a clean shutdown.
