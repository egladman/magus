# MGS3045: a ci gate over the write paths nothing runs

`magus job fork`, `magus job apply` and `magus\job.put` refused a job record
because `ci` runs a target over its write paths that the job never runs:

```text
[MGS3045] ci runs `lint .` over the write paths (it reads changes/**/*.md), and
  neither the check nor a goal runs it: add the goal
  {"id":"lint","kind":"check","check":{"target":"lint","project":"."}} to goals,
  or permit it in deviations
```

Nothing was written to the job store.

## Why

A job graded only on its check can pass while the gate that will judge its
change fails. The failure then surfaces after integration, where nobody holds
the files any more.

## Which project a gate names

A write inside a project gates on that project's target when its target reads
the file. A write under `libs/x` asks for `test libs/x`, and a check of `test .`
does not satisfy it, since the root's tests do not run the module's.

The root keeps a gate of its own over the file in two cases:

- The root's target spells the path out in its sources, as `libs/**/*.go` or
  `docs/reference/codes/**/*.md` do. Both targets then read the file, so the
  write asks for both. A bare `**/*.go` is a language default and spells out
  nothing.
- The project has no such target, or its target does not read the file.

A project binding spells it carries unresolved cannot say which targets it
runs. Its gate stays on the root, and the fork lists that project among the
checks it did not run.

A row is judged on the write paths each write adds. A live row keeps a deviation
naming `test .` over a sub-project write, and a re-apply adding no path is not
asked again. A record that adds a path there is asked for `test libs/x`.

## What to do

- Add the goal the problem prints, so the worker runs the target.
- If the root runs the gate once after integrating every job, permit the
  problem with `<target> <project>` as its subject:

```json
"deviations": [
  { "code": "MGS3045", "subject": "lint .", "reason": "the root runs it" }
]
```

`magus describe job <id>` lists the gates not run and the goals to add.
