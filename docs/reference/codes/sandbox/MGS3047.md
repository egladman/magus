# MGS3047: a record from a newer magus

A magus record was written by a newer magus. It names a requirement this
build does not have, or a schema version past the one this build reads:

```text
[error] run history is unreadable, so this run sizes claims from declarations
  and records no history: [MGS3047] forecast: history version 9 in
  "~/.local/state/magus/history.jsonl" was written by a newer magus (this build
  reads up to 8) and is left alone
```

Three records are read this way:

- A **job row** that requires a feature this magus lacks.
- A **stored output** imported with `magus query output`, whose
  `api_version` is newer or whose `requires` this magus does not implement.
- The **run history**, whose version is newer than this build reads.

## What still works

The record stays on disk unchanged, and nothing rewrites it. A newer magus
finds it where it left it.

- A job row stays listed and graded, and `magus job ls` names it as read-only.
  Writing it, a delete included, is refused with this code: a reader that
  cannot act on its content could corrupt it. Every other row stays writable.
- A stored output is not imported. Nothing reaches the command, so it never
  prints half an input.
- Without its history, a run sizes each claim from what the target declares,
  as a target with no history does. It records no history, and it says so once.

## What to do

Run the magus that wrote the record, or upgrade this one to it. Nothing needs
cleaning up: the next read by a build that has the requirement reads it.

An added field is not this code. A reader ignores a member it does not know, so
an added field never moves a record past an older reader.
