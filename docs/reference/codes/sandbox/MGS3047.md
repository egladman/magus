# MGS3047: store records from a newer magus skipped

A magus store held records a newer magus wrote, each naming a requirement this
build does not have. This magus skipped them and read the rest:

```text
[warn] MGS3047 history: skipped 212 of 1058 run-history lines because a newer
  magus wrote them (requires curve-v2); those targets size memory from
  declarations this run
  fix: run the newer magus; the lines are kept and read again once this one is upgraded
```

Run history, sessions and job rows are read this way: each record says what a
reader needs, and a reader that lacks it leaves that record alone.

## What still works

- Every record this magus can read is read. Only the skipped ones are missing
  from the answer, and the line says how many.
- The skipped records stay on disk unchanged, and a rewrite of the store carries
  them back out whole, so the newer magus finds them where it left them.
- The command goes on. For run history, the targets whose records were skipped
  size their claims from what they declare, as a target with no history does.

It fails a command only when the record skipped is the one thing the command was
asked for, such as a stored output a newer magus wrote. Then it is an error.

## What to do

Run the magus that wrote the records, or upgrade this one to it. Nothing needs
cleaning up: the next read by a build that has the requirement reads them.

An added field is not this code. A reader ignores a member it does not know, so
an added field never moves a record past an older reader.
