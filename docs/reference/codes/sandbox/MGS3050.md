# MGS3050: a store line that cannot be decoded

A line in a magus store did not decode as a record:

```text
[error] run history is unreadable, so this run sizes claims from declarations
  and records no history: [MGS3050] ~/.local/state/magus/history.jsonl:812:
  unexpected end of JSON input
```

A store is JSON Lines: one record per line. This line is not valid JSON, or it
has the wrong shape for the store. An edit by hand leaves one, and so does a
disk that filled mid-write. A last line with no newline is not this code: it is
an append in flight, left unread until its writer finishes.

A corrupt line is not a newer one. A record a newer magus wrote decodes, names
what it requires, and is kept for that magus ([MGS3047](MGS3047.md)). This line
holds nothing any magus can read.

## What still works

magus does not read past the line. Skipping it could drop a record that
matters, such as the lease a job holds, and the guard would read a dropped
lease as nothing leased. So the store is not read at all:

- A command that needs the store, such as `magus job`, stops before it writes
  anything.
- A run goes on without its history, sizing claims from declarations, and says
  so once.
- The guard goes on without a memo it could not read, and logs why.

## What to do

Open the store at the line named. Delete the line, or fix it by hand if you
know what it held. If lines go bad again, look for what writes the store
besides magus, or for a disk that fills.
