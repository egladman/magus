# MGS3057: a ci run changed the working tree

A ci run always verifies with `rw` and `update` stripped. When the run carried
`rw` (`magus run ci:rw`, or `default_charms: [rw]`) and a target failed, ci runs
that target under `rw` if the target itself declares a write and reads `rw`, then
verifies again. A stale output a verify pass regenerated is retried once. Either
way the tree no longer matches HEAD, so the run fails and names what moved:

```text
[MGS3057] ci changed 1 version-controlled file: a.txt (repaired: .:tidy).
  Commit them and run ci again; an uncommitted repair gets no verdict
```

A failure no repair cleared comes first, then this line.

## What to do

Read the change, commit it, and run ci again. The next run verifies the new commit
and records its verdict.

To check without writing, pass `--no-default-charms`. A CI runner does this, so
its run never repairs.

## What it does not see

The comparison reads the working tree's changed paths before and after the run. A
file inside an untracked directory or an ignored file is not in that set.
