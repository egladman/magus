# MGS2014: a tool cache resolves outside the checkout

A tool's cache lives outside the checkout that runs it, so every checkout on the machine
shares it:

```text
magus guard denied `.magus/custom-gcl run ./...`; [MGS2014] GOLANGCI_LINT_CACHE is unset, so the tool falls back to its shared user cache; run `magus run golangci-lint <project>`, which keeps the cache in /work/repo/.magus/golangci-lint
```

## Why

golangci-lint keeps its results in one cache directory and answers from it. Left to the
default, that directory is the user's cache folder, shared by every checkout: one shared
cache held 10,202 paths from 5 other checkouts, and a run in a sixth answered from them
and hid findings the checkout itself would report.

`magus run golangci-lint <project>` points `GOLANGCI_LINT_CACHE` at `.magus/golangci-lint`
under the checkout, so the cache holds only that checkout's results. A direct
`.magus/custom-gcl run` or `golangci-lint run` sets nothing, and uses whatever the
environment says.

## Resolution

Run the target:

```sh
magus run golangci-lint <project>
```

To run the tool directly, point its cache under the checkout first:

```sh
GOLANGCI_LINT_CACHE="$PWD/.magus/golangci-lint" .magus/custom-gcl run ./...
```

`magus doctor` reports the same code when the effective cache is outside the checkout,
with the location it resolves to.
