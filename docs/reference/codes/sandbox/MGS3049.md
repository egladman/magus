# MGS3049: a legacy store left beside its replacement

magus found a store's old file beside the file that replaced it:

```text
[error] MGS3049 job: jobs.json, written by an older magus, sits beside jobs.jsonl;
  both are left alone
  fix: once no older magus writes it, reconcile its records, then `mv jobs.json jobs.json.old`
```

An older magus may still be writing the old file. Reading only the new one would
lose what it writes, and folding the old one in would race it. Two files would be
two accounts of the same records, so magus reads neither.

## What still works

- Neither file is changed, moved or deleted.
- The older magus that writes the old file keeps working against it.
- Commands that do not open this store run as usual.

The command that needed this store stops before it writes anything.

## What to do

1. Find what still writes the old file: an older magus binary, a server it
   started, or a script. Stop it, or upgrade it.
2. Reconcile any records only the old file holds into the new store.
3. Set the old file aside so it is kept but no longer read:

   ```sh
   mv jobs.json jobs.json.old
   ```
