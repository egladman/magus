# MGS3054: a plan shard computes another project's prerequisite

`magus affected <target> --plan` packs the affected units into shards in two
stages ([ADR 0027](../../../decisions/0027-shared-prerequisites-run-once-in-stage-zero.md)).
A computing prerequisite that a unit of another project needs runs in stage zero, and
every stage-one shard replays it from the cache stage zero leaves. The plan checks
that before it prints:

```text
[MGS3054] ci: stage one computes .:build beside a unit of another project that
needs it; stage zero must compute it
```

## Why

On a stage-one shard, the other project's work would run in its dependent's runner.
The dependent then waits for it, and every shard that holds a dependent computes it
again. The planner moves each such prerequisite to stage zero, so the refusal means
the planner broke its own rule. A plan that ran anyway would gate the shard on work
another project owns.

## Resolution

There is nothing to change in the workspace. Report the plan and the magus version
that printed it. `magus affected <target> --plan -o json` prints the `stage_zero` and
`matrix` shards the planner chose.
