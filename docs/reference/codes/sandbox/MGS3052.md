# MGS3052: the disk is full

A run or a bootstrap failed with `no space left on device` while the filesystem it
ran on was below `disk.critical_free_mb`, or `magus job fork` reclaimed space and the
disk stayed below that floor:

```text
[MGS3052] the disk is full: 151 MiB free where this ran.
  Run `magus buzz -e 'import "magus/reclaimdisk" as r; r\reclaimNow();'`
```

## Why

Both facts must hold. A test fixture can print the same text, so the text alone
proves nothing, and a low disk alone did not fail the run.

## Fix

Run the command the message names. It trims each cache a spell gives a budget, removes
worktrees that hold nothing to lose, and prints what it did and what it left for you.
A worktree with uncommitted files, unpushed commits or a lock is yours to review, and
magus never removes one.
