# MGS4010: narrowed wait past a baseline writer

A step that reads what another step writes waits on the writing TARGETS it
overlaps, not on that whole step. This notice fires when the writing step also
runs a target whose write footprint is the project baseline rather than its own
`ctx.writesFiles` declaration.

```text
[MGS4010] docs ci waits on the targets of . ci it overlaps rather than all of it, and .
  lint declares no writes of its own, so anything it writes outside . ci's declared globs
  is no longer ordered against the reader; declare its ctx.writesFiles
```

## Why it fires

Every overlap the footprints NAME is its own derived edge, and the reader waits
on each one. The gap is what no glob names. A whole-step wait used to cover such
a write by accident: the reader stayed blocked until the step ended, so whatever
that step wrote along the way landed first, declared or not.

Waiting on the writer alone removes the accident. It removes no ordering magus
derived, and an undeclared write was never ordered on any other path either:
nothing in the model knows it happens.

## What to do

Declare what the named target writes:

```buzz
export fun lint(ctx: magus\Context, args: [str]) > void {
    ctx.writesFiles("reports/lint.json");
    go["go-vet"](ctx);
}
```

A target that genuinely writes nothing needs no change, and the notice then
reports only that magus cannot prove it. A target that EDITS files it does not
own declares `ctx.modifiesExistingFiles` instead, which keys the same way without
claiming the bytes.
