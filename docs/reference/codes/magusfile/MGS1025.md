# MGS1025: a charm can unselect a JSON op's format

An op that declares `returns_json` promises its stdout is one JSON document, and
magus decodes it into the `json` member of the exec record. A charm rewrites that
same argv at run time. If a charm can reach the argument that selected JSON, the
promise becomes conditional on which charms are active - and it breaks under a charm
the op's author never ran, which is the worst way to find out.

## Why this is a warning, not a prohibition

magus cannot tell which argument selects a tool's output format, so it cannot prove
a given patch is wrong. A `replace` that rewrites an unrelated flag is fine, and a
`replace` swapping one JSON mode for another (`--format-version 1` to `2`) is still
JSON.

What it CAN say is that an append is the only shape that cannot possibly unselect a
format. Anything else deserves a second look - so this reports, and you either
rewrite it or declare that you checked.

```text
spell rust op cargo-metadata: charm "gha" applies "replace" to an op that declares
returns_json; it can rewrite the argument selecting JSON, so express it as an
append ("add") instead
```

## Resolution

Either rewrite the charm as an append, or declare the exception with a reason:

```buzz
export fun mgs_listJSONCharmExceptions() > {str: str} {
    return {
        "cargo-metadata": "the gha charm swaps --format-version 1 for 2; both are JSON",
    };
}
```

A reason is required for the same reason `mgs_listUnprobedBins` requires one: an
undeclared exception is indistinguishable from an author who never considered it.

Rewriting as an append is the other route. A charm that adds a flag composes with the format
flag rather than competing with it:

```buzz
// Rejected: replace can land on the argument that selected JSON.
"gha": replace(args, "--format", "--format=github"),

// Accepted: the format argument survives, the charm adds to it.
"gha": append(args, "--quiet"),
```

If a charm genuinely needs a DIFFERENT output format, it is not a charm on this op -
it is a different op. A charm expresses one intent applied to the same work
(`rw` makes a check write, `debug` adds verbosity); changing what the command
returns is different work, and `go-mod-edit` / `go-mod-edit-json` is the shape that
models it - siblings, one returning a verdict and one returning data.
