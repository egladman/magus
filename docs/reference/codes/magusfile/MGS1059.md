# MGS1059: a read through a workspace that is not connected

A target can read another workspace's files by the plain path through its symlink:

```buzz
ctx.readsFiles([".magus/workspaces/magus/.golangci.yml"]);
```

Where no `magus` entry connects that workspace, the symlink is absent and the read
could key nothing:

```text
[MGS1059] .:lint reads .magus/workspaces/magus, not connected here: add
{name: magus, path: ...} to knowledge.workspaces in $XDG_CONFIG_HOME/magus/magus.yaml
```

## Why

A read that matched nothing would key the target on none of the files it uses, so a
cached pass would replay after the other workspace changed. Refusing is the only answer
that cannot pass for a check.

## Resolution

- **On your machine.** Add both workspaces to `knowledge.workspaces` in the user config.
- **In CI.** Check the other workspace out and write the user config in the job, or
  run only the targets that read nothing through `.magus/workspaces`.
