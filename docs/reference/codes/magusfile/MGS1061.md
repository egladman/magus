# MGS1061: depends_on names the root project

```buzz
magus\project({
    "depends_on": ["..", "../proto"],
});
```

```text
[MGS1061] project "console": depends_on ".." names the root project; a ctx.needs
on a root target carries that edge
```

## Why

The root project's directory is the whole workspace, so an edge to it is an edge to
everything the root claims. A run orders every target behind the root's target of the
same name, so `docs lint` waits for the root's `lint` and `docs build` for its `build`,
whether or not the docs read anything they produce. In CI that edge pulled the root's
build and lint chains onto the shard that ran the docs and the console.

## Resolution

- **A target needs a root target.** Call it: `ctx.needs(workspace\symbol_digest_generate)`
  with `import "project/.." as workspace;`. The load folds that call into the project's
  dependencies, so affected and the cache still see the root, through the one target
  that reads it.
- **A target reads root files.** Declare them with `ctx.readsFiles` and
  `workspace\file(...)`.
- **A library the root holds.** Make it a project of its own and name that project.
