# MGS1054: a listed workspace is missing

`knowledge.workspaces` in the user config connects every listed workspace to every
other. Each load in a listed workspace checks every entry before it evaluates a
magusfile, and stops when one names no workspace:

```text
[MGS1054] knowledge.workspaces entry buzzed points at /home/me/Repos/buzzed, which
does not exist; delete the entry at /home/me/.config/magus/magus.yaml:6, or restore
the checkout
```

An entry fails when its path does not exist, is not a directory, or holds no
`magus.yaml`, `.magus.yaml` or `magusfile.buzz`.

## Why

A target in one workspace may read the other through `.magus/workspaces/<name>`. Skipping
the entry would leave that path dangling and every read through it keying nothing, so
the run would look checked against files it never saw.

## Resolution

- **The checkout moved.** Point the entry's `path` at it.
- **The checkout is gone for good.** Delete the entry. The next load removes
  `.magus/workspaces/<name>` from every tree that held it and prints each removal.
