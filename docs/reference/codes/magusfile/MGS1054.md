# MGS1054: a use entry names no workspace

`use` in `magus.yaml` stitches another magus workspace into this one by local path, the
way `go.work` stitches Go modules. A target reads the used workspace's files as
`@<name>/<glob>`, and a magusfile imports its Buzz modules as `import "@<name>/<path>"`.

magus resolves every entry before it evaluates any magusfile, and stops when one names
no workspace:

```text
[error] [MGS1054] magus.yaml use "magus": /src/magus does not exist, so its rules
cannot apply here. Point path at the root of a magus workspace, or remove the entry.
```

An entry fails when its path:

- does not exist, or is not a directory;
- holds no `magus.yaml`, `.magus.yaml` or `magusfile.buzz`;
- is this workspace's own root.

## Why

A used workspace lends rules: its lint configuration and its custom linters. An entry
magus skipped would leave those rules unapplied while every run still passed, so the
code would look checked by rules that never ran. Stopping the load is the only answer
that cannot be mistaken for a pass.

## What to do

Point `path` at the root of the workspace, relative to the directory holding
`magus.yaml` or absolute:

```yaml
use:
  - name: magus
    path: ../magus
    share: [lint]
```

Clone or check out the used workspace there first. If this workspace no longer reads its
rules, remove the entry.
