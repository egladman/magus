# MGS1041: a remote spell import is not pinned

A magusfile imports a spell from a registry by tag alone:

```text
[error] [MGS1041] remote spell "oci://ghcr.io/o/r/spells/x:latest" names no manifest
digest: a tag can move, so pin it with @sha256:<digest>
```

## Why

A remote spell runs code magus did not ship, so the magusfile has to say exactly which
bytes. A tag is a pointer the publisher can move; the manifest digest is the content
itself, and the pull checks every byte against it. Warning and loading anyway would run
exactly the code the pin exists to refuse.

## What to do

Append the digest the publish printed, `@sha256:<digest>`. A tag may stay beside it for
readers; the pull ignores it. See [Remote spells](../../remote-spells.md).
