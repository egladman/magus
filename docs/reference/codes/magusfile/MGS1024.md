# MGS1024: spell op named against the formula

A spell and its ops are public API: a magusfile writes `typescript["eslint"](ctx)`,
so a rename breaks every workspace that composed it. The
[naming formula](../../../concepts/spell-naming.md) decides both names from the op's
own argv, which makes a drifted name decidable rather than a matter of taste.

That matters because this is a failure taste cannot see. `docker["docker-push"]`
reads as "docker docker push" and nobody notices while writing it; the stutter only
becomes expensive once fifty callers exist and none can be changed cheaply.

## What fires it

**A spell named after a binary it forks.** Reported once against the spell, because
renaming its ops one at a time only papers over the real fault:

```
spell docker: the spell is named after "docker", a binary it forks (op docker-build)
```

A spell is named for the DOMAIN it adapts, never for the tool that happens to drive
it today: `rust` not `cargo`, `oci` not `docker`. A spell named after a binary starts
lying the moment a second binary joins it, and a second one always joins - the `oci`
spell drives `docker`, `trivy` and `hadolint`.

The exception is a language whose canonical name IS its toolchain binary. Go's name
is Go and the command is `go`. A spell that declares that language (`mgs_getLanguage`)
is naming its domain, so it is exempt and its ops drop the redundant prefix instead.

**An op name the formula does not yield.**

```
spell go op go-build: the formula yields "build" from "go build"
```

## Resolution

Rename the op to what the formula yields, or declare the deviation with a reason:

```buzz
export fun mgs_listNamingDeviations() > {str: str} {
    return {
        "node-test": "the formula yields `node`, which names the runtime rather than the action",
    };
}
```

A reason is required for the same reason `mgs_listUnprobedBins` requires one: an
undeclared deviation is indistinguishable from an op nobody thought about.
