# MGS1042: a remote spell does not match its digest

The registry answered, but with bytes other than the ones the import pins:

```text
[error] [MGS1042] remote spell oci://ghcr.io/o/r/spells/x@sha256:<pinned>: the registry
served bytes that do not match the pin: oci: manifest does not match the digest its
reference pins: ... served sha256:<actual>
```

## Why

The digest is the only proof that the code about to run is the code the magusfile's
author chose. A registry is content-addressed, so a mismatch means the host, a proxy, or
something between them changed the bytes. magus cannot tell which, so it loads nothing
and caches nothing.

## What to do

Do not replace the pin with the reported value until you know why it differs. Pull the
same reference from another network, or ask the publisher for the digest their publish
printed. See [Remote spells](../../remote-spells.md).
