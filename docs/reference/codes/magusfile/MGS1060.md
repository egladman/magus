# MGS1060: a source glob reaches into another project

A `sources` glob names the files that key a project's cache and pull it into the
affected set. Its static prefix, the directories before the first wildcard, must lie
in the project's own tree:

```buzz
magus\project({
    "sources": ["../README.md", "../proto/magus/**/*.proto"],
});
```

```text
[MGS1060] project "docs": source glob "../README.md" reaches into project ".",
which owns "README.md"; read it with ctx.readsFiles on the targets that do
```

It fires for a glob that reaches out of the project, as above, and for one that
names a project nested inside it, such as the root's `libs/embed/testdata/*` when
`libs/embed` is a project. A broad glob over the project's own tree, such as the
root's `**/*.go`, names no other project and passes.

## Why

The file belongs to the other project. Claimed as a source here, every target of
this project keys on it and every edit to it marks this project affected, while
the targets that read it are the only ones it should move. The claim also couples
the two projects in the CI plan with no edge anyone declared.

## Resolution

- **Another project's files.** Name the project in `depends_on`. Its changes then
  reach this project through the declared edge.
- **The root's files.** Read them with `ctx.readsFiles([workspace\file("README.md")])`
  on the targets that read them, where `workspace` is `import "project/.."`.
  `depends_on` cannot name the root ([MGS1061](MGS1061.md)).
- **A file this project should own.** Move it into the project's tree.
