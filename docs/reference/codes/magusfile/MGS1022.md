# MGS1022: spell op bin without a version probe

`magus doctor` found a spell op whose bin is invisible to every cache key: it is
neither `argv[0]` of the spell's version probe (`mgs_getVersionCommand`), nor of
any named probe (`mgs_getVersionCommands`), nor declared as a deliberate
opt-out (`mgs_listUnprobedBins`).

```text
[MGS1022] 1 spell op bin(s) contribute no version probe to the cache key;
upgrading one changes verdicts while every cache entry replays. Add a named
probe (mgs_getVersionCommands) or declare the opt-out with a reason
(mgs_listUnprobedBins) (see .../MGS1022/)
  spell go op go-fmt: bin "gofmt" has no version probe; add "gofmt" to
  mgs_getVersionCommands, or declare it in mgs_listUnprobedBins with a reason
```

## Why

A PATH binary pinned by no manifest is a cache input nothing hashes. Upgrading
it changes which files pass - a new golangci-lint release enables new checks, a
new hadolint flags new Dockerfile patterns - while every cache entry keeps
replaying the verdict the old binary produced. The fix has always been policy
(see the docker spell's hadolint note): each verdict-deciding binary a spell
drives contributes its own version probe, so an upgrade moves the cache key.

Policy that lives only in comments decays. This check makes it mechanical: every
op bin must be accounted for, either by a probe or by a declared exception with
a stated reason. The two real exceptions in the built-ins show what a legitimate
opt-out looks like - `gofmt` ships version-locked inside the go toolchain (so
`go version` already covers it), and `cargo` is rustup-locked to `rustc`.

Three shapes are skipped rather than reported:

- an empty bin (a no-op marker op, like an opaque spell's aggregate target);
- `sh` (a `sh -c` wrapper's real tool lives inside the script string, so the
  bin is unattributable);
- for a spell that opts in to package-manager substitution
  (`mgs_getPackageManagerBin`), the substitutable manager bins plus `node`: the
  recorded manager is swapped per project at fork time, so no single probe argv
  can name it.

## Resolution

Give the bin a named probe, or declare the opt-out with the reason:

```buzz
// Before: gofumpt forks from PATH with nothing in any cache key to notice an upgrade.
export fun mgs_getVersionCommands() > {str: [str]} {
    return {"golangci-lint": ["golangci-lint", "--version"]};
}

// After (preferred): a named probe, so upgrading gofumpt moves the key.
export fun mgs_getVersionCommands() > {str: [str]} {
    return {
        "golangci-lint": ["golangci-lint", "--version"],
        "gofumpt": ["gofumpt", "--version"],
    };
}

// After (when another probe genuinely covers the bin): a declared opt-out.
// The reason is required - an opt-out without one reads as a forgotten probe.
export fun mgs_listUnprobedBins() > {str: str} {
    return {"gofmt": "ships with the go toolchain; `go version` covers it"};
}
```

A named probe records `UNPROBED` when the tool is absent and moves the cache
key when it is installed, so a workspace that never runs the op pays nothing
for declaring it.

## What this is NOT

- **Not a hard error.** The op still runs; nothing blocks the build. It is a
  `magus doctor` finding, not a spell load failure.
- **Not a check over workspace-local spells.** Only built-in spells bound to a
  workspace project are examined: the covered/uncovered judgment needs the
  spell's raw declaration, which doctor can only reach for built-ins.
- **Not a demand that every spell probe every tool.** A bin a spell never forks
  needs nothing, and a bin another probe genuinely covers is one declared
  opt-out away from silence.
