# MGS1053: a path declared both produced and edited

magus stops loading a workspace when one target declares a path in both modes of
`ctx.writesFiles`: once as a file it produces, and once with
`editsExistingSource: true`. The two calls may be far apart in the body, or reached
through a helper; calls accumulate, so magus reads them together.

```text
[MGS1053] .: target "generate": ctx.writesFiles declares "gen/**" as produced and
"gen/version.go" with editsExistingSource: true, which overlap, and a path has one
mode: a produced file is replayed and cleaned, an edited source is hashed and never
replayed
```

The same path written twice and two globs that can match one file are both caught:

```buzz
import "magus";

export fun generate(ctx: magus\Context, args: [str]) > void {
    ctx.writesFiles(["gen/**"]);
    ctx.writesFiles(["gen/version.go"], editsExistingSource: true); // gen/** produces it
}
```

## Why

The two modes promise opposite things about one file. A produced file is magus's: it
is snapshotted after the run, replayed on a cache hit, kept out of the source hash,
and deleted by `magus clean`. An edited source is someone else's: it is part of the
source hash and is never replayed or deleted. A file cannot be both, and either
choice made on the author's behalf would be silently wrong: replaying it overwrites
the hand-written part, and not replaying it leaves a cache hit without the output.

## Resolution

Decide who owns the file.

- **The target creates it whole every run.** Drop it from the `editsExistingSource`
  call; it is an output.
- **The file is authored and the target changes part of it.** Narrow the produced
  glob so it no longer matches the file, with a `!` exclusion if that is simpler:
  `ctx.writesFiles(["gen/**", "!gen/version.go"])`.

See [Files a target edits rather than
produces](../../../concepts/cache.md#files-a-target-edits-rather-than-produces).
