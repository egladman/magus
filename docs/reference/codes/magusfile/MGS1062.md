# MGS1062: a cross-project ctx.needs with no depends_on

```buzz
import "project/../libs/textsearch";

magus\project({"depends_on": ["../proto"]});

export fun lint(ctx: magus\Context, args: [str]) > void !> any {
    ctx.needs(textsearch\lint);
}
```

```text
[MGS1062] console: target "lint": ctx.needs names a target in "libs/textsearch",
which depends_on does not name; add "../libs/textsearch" to depends_on
```

## Why

A `ctx.needs` on another project is an edge between projects. Left out of
`depends_on`, the only record of it is one call deep inside one target body, and a
reader of the project's declaration cannot see what it is coupled to. The edge is the
same either way: the load folds each such call into the project's dependencies.
Requiring the declaration keeps the project's couplings in one place.

A `ctx.needs` on the root project is the exception. [MGS1061](MGS1061.md) refuses
naming the root in `depends_on`, so the call is that edge's only spelling.

## Resolution

Add the project the error names to `depends_on`, in the spelling it gives.
